# 12.1 装备 Builder Agent 设计

## 结论

使用一个 AgentScope 2.x `Agent`（`ReActConfig`）作为对话协调器，配一个完全确定性的装备优化器。模型不得自行编造装备、属性或掉落来源；所有数值结论必须来自工具返回。

## Builder 输入

- 用户身份与已保存配装。
- SimC 字符串，或手动选择职业、专精、场景。
- 场景：团本或大秘境。
- 目标属性：绿字比例，或面板百分比目标。
- 可选限制：锁定装备、排除副本、只看已拥有装备、允许制造装备、必须保留四件套。
- 用户逐件选择实际插入的宝石；每件装备只能添加到该物品 `max_sockets` 上限。
- 默认装备等级：神话 6/6（334）；制造装备使用自己的最高可用等级。

## 固定计算规则

1. 读取职业、专精、装备槽、护甲和武器资格。
2. 读取当前装备，计算装备静态绿字、用户已选择的宝石和合剂；忽略空孔、触发型绿字与武器附魔。
3. 百分比换算只考虑通用基础暴击 5%、基础精通 8% 与该专精精通系数；暂不计天赋赠送属性。
4. 保留用户锁定件、四件套约束、唯一装备和制造/美化限制。
5. 从掉落、制造和套装数据中生成合法候选。
6. 优化器按“目标属性偏差”评分，并以换装数量、获取难度作为次级排序条件。
7. 返回最优方案、当前与目标差值、每一处换装收益、掉落来源和优先刷本顺序。

### 宝石交互

- Builder 不自动假定角色拥有任何后加孔，也不自动填满宝石。
- 装备卡片显示 `已用孔数 / 最大孔数`，用户点击空孔选择宝石。
- 项链、戒指、头、护腕和腰带的常规单件上限为 1；物品自身数据可以覆盖这个默认值。
- 只有用户实际选择并插入的宝石才进入绿字计算。
- 更换装备时清空该槽的手动宝石选择，要求用户重新确认，避免把旧装备插槽错误继承到新装备。

## AgentScope 工具

第一版只需要六个工具：

1. `parse_simc(simc_text)`：解析角色、专精、装备 ID、装等、宝石和附魔。
2. `get_spec_profile(class_key, spec_key, content_type)`：读取绿字推荐、转换系数和版本优先标记。
3. `get_item_candidates(...)`：按槽位、职业资格、装等和来源筛选合法装备。
4. `calculate_stats(loadout, consumables)`：确定性计算绿字数值与面板百分比。
5. `optimize_loadout(request)`：搜索并返回若干套最接近目标的合法配装。
6. `rank_farming_targets(current, target)`：按可替换部位汇总副本、Boss 和预期提升。

工具只返回结构化 JSON；最终回答使用 Pydantic 结构化输出，至少包含：`summary`、`current_stats`、`target_stats`、`changes`、`farming_priority`、`warnings`。

## 一次对话的执行流

```text
用户问题 / SimC
      ↓
Agent 识别职业、专精、场景和限制
      ↓
解析 SimC → 读取规则与候选 → 计算当前属性
      ↓
确定性优化器生成并校验方案
      ↓
Agent 用中文解释“为什么换、去哪里拿、还差多少”
```

用户追问“少一点急速、多一点全能”时，Agent 只更新约束并重新调用优化器，不在自然语言里手算。

## 数据来源

- `data/12.1-season2-loot.json`：地下城和团本装备、等级、静态属性与来源。
- `data/12.1-season2-crafted-gear.json`：制造装备与自定义绿字规则。
- `data/12.1-season2-tier-sets.json`：套装和转化关系。
- `data/12.1-season2-consumables.json`：宝石、合剂等可计入属性的数据。
- `data/12.1-secondary-stat-conversions.json`：绿字百分比转换。
- `data/12.1-stat-recommendations.json`：专精与场景的目标比例。
- `data/12.1-wowhead-bis.json`：展示和对比用 BIS，不作为优化器真值。

## 第一版明确不做

- DPS 模拟。
- 多 Agent 协作。
- 向量数据库或 RAG。
- 让模型执行任意 Python 或 Shell。
- 让模型直接修改装备数据库。

数据规模很小，第一版直接加载 JSON 并在内存过滤；用户、会话和已保存配装使用 SQLite。只有数据量或并发实测不足时再换数据库或增加独立服务。

## 安全边界

- API 密钥只从 `.env` 读取，不进前端、不进日志、不进数据库。
- 工具参数使用 Pydantic 校验；物品 ID、槽位和职业资格在服务端再次验证。
- 每份方案都在返回前重新计算一次，禁止 Agent 覆盖计算结果。
- 联网更新与正式配装数据库分离，抓取结果校验后才能发布。
